# Vibe Kanban 项目同步规则

## 核心原则

本项目使用 Vibe Kanban 看板系统进行项目管理，通过 MCP 协议与 Trae IDE 集成。AI 必须在开发过程中自动同步项目进度到 Kanban，确保看板始终反映最新的开发状态。

本规则同时适用于：
- **当前项目内**的开发同步
- **跨项目**场景：当用户在 Trae 中创建或打开其他项目时，自动识别并同步到 Kanban

## 规则一：项目创建自动同步

当用户要求开始一个新项目的开发时，AI 必须执行以下步骤：

1. **分析项目需求**：理解用户描述的项目目标、功能范围和技术要求
2. **拆解项目模块**：将项目拆解为可执行的模块任务（如：前端开发、后端API、数据库设计、测试等）
3. **调用 MCP 工具创建项目**：使用 `create_project` 工具在 Kanban 上创建项目，并传入 `modules` 参数自动创建任务
4. **确认同步结果**：向用户展示 Kanban 上创建的项目和任务列表

### 示例触发场景
- 用户说："帮我开发一个电商系统"
- 用户说："我要做一个博客平台"
- 用户说："开始XX项目的开发"

### 示例调用
```
create_project({
  name: "电商系统",
  description: "基于Next.js的全栈电商系统，包含商品管理、购物车、订单等功能",
  modules: ["数据库设计与建模", "后端API开发", "前端页面开发", "支付集成", "测试与部署"],
  milestones: [
    { title: "MVP版本", date: "2026-06-01" },
    { title: "正式上线", date: "2026-07-01" }
  ]
})
```

## 规则二：跨项目自动识别与同步

当用户在 Trae 中打开或创建一个新项目（非 Vibe Kanban 项目本身）时，AI 应主动识别项目信息并询问是否同步到 Kanban。

### 识别项目信息的优先级
1. `package.json` 的 name + description
2. `README.md` 的项目标题和描述
3. 项目目录名

### 执行步骤
1. **自动识别**：读取项目根目录的配置文件，获取项目名称和描述
2. **推断模块**：根据项目类型（前端/后端/全栈/工具库）自动推断模块结构
3. **确认同步**：向用户展示识别结果，询问"是否将此项目同步到 Kanban？"
4. **创建项目**：用户确认后，调用 `create_project` 创建项目并拆解任务

### 模块拆解参考
- **前端项目**：UI组件开发、页面路由、状态管理、API对接、样式系统
- **后端项目**：数据库设计、API开发、认证授权、业务逻辑、中间件
- **全栈项目**：前端开发、后端API、数据库设计、认证系统、部署配置
- **工具/库项目**：核心功能、API设计、文档、测试、示例

## 规则三：模块开发进度自动同步

当 AI 开始编写某个模块的代码时，必须自动将该模块对应的 Kanban 任务状态更新为 `in_progress`。

### 触发条件
- AI 开始创建或修改某个模块的文件时
- AI 开始实现某个功能模块时
- 用户明确指示"开始做XX模块"时

### 执行步骤
1. **识别当前模块**：根据正在编写的代码确定所属的功能模块
2. **查找对应任务**：使用 `list_tasks` 工具在项目中查找与该模块匹配的任务
3. **更新任务状态**：使用 `update_task` 工具将任务状态改为 `in_progress`
4. **无需每次确认**：这是自动行为，不需要每次都询问用户

### 示例
当 AI 开始编写用户认证相关代码时：
```
list_tasks({ projectId: "xxx", status: "todo" })
// 找到 "后端API开发" 或 "用户认证模块" 任务
update_task({ taskId: "yyy", status: "in_progress" })
```

## 规则四：任务完成自动同步

当 AI 完成某个模块的开发时，应将对应任务状态更新为 `in_review`（而非直接设为 done，因为需要用户确认验收）。

### 触发条件
- 某个模块的所有代码文件已编写完成
- 某个功能模块的实现已结束
- 用户明确指示"XX模块做完了"时

### 执行步骤
1. 使用 `update_task` 将任务状态改为 `in_review`
2. 调用 `add_dev_log` 写入一条 `complete` 类型的开发日志
3. 向用户简要汇报该模块已完成，等待验收

## 规则四-B：开发日志自动写入

AI 在开发过程中，必须在关键节点自动调用 `add_dev_log` 工具写入开发日志，实现开发过程可追溯。这是强制性行为，无需每次询问用户。

### 事件类型与触发时机

| eventType | 触发时机 | 日志内容示例 |
|-----------|---------|-------------|
| `start` | 开始编写某个模块的代码时 | "开始开发用户认证模块，采用 JWT + Session 双模式" |
| `decision` | 做出技术选型、架构设计等决策时 | "选择 Redis 作为会话存储，理由：高并发场景下性能优于内存存储" |
| `problem` | 开发过程中遇到阻碍性问题时 | "跨域请求被浏览器拦截，需配置 CORS 中间件" |
| `fix` | 修复 Bug 或解决上述问题时 | "修复用户注册时邮箱校验未生效的问题，原因是正则表达式写反" |
| `refactor` | 进行重要代码重构时 | "将认证逻辑从路由层抽离为独立中间件，提升复用性" |
| `complete` | 模块开发完成时（与规则四联动） | "用户认证模块开发完成，包含登录/注册/密码重置功能" |

### author 字段格式

`author` 参数用于标识日志的写入者，格式为 `Agent类型-用户名`：
- 使用 Trae 的用户：`Trae-张三`
- 使用 Cursor 的用户：`Cursor-李四`
- 使用其他 Agent 的用户：`AgentType-用户名`

AI 应在首次对话时询问用户的名称偏好，或从项目配置中读取。如果无法确定，使用 `Trae-用户` 作为默认值。

### 执行步骤

1. **识别关键节点**：在开发过程中自动判断当前是否处于上述触发时机
2. **查找对应任务**：使用 `list_tasks` 找到当前模块对应的任务
3. **写入开发日志**：调用 `add_dev_log`，传入 taskId、eventType、content、author
4. **与状态同步联动**：`start` 事件与 `update_task({ status: "in_progress" })` 联动，`complete` 事件与 `update_task({ status: "in_review" })` 联动

### 示例

当 AI 开始编写用户认证模块代码时：
```
// 1. 更新任务状态
update_task({ taskId: "yyy", status: "in_progress" })

// 2. 写入开发日志
add_dev_log({
  taskId: "yyy",
  eventType: "start",
  content: "开始开发用户认证模块，采用 JWT + Session 双模式",
  author: "Trae-张三"
})
```

当 AI 做出技术选型决策时：
```
add_dev_log({
  taskId: "yyy",
  eventType: "decision",
  content: "选择 Redis 作为会话存储，理由：高并发场景下性能优于内存存储",
  author: "Trae-张三"
})
```

### 写入原则

- **简洁摘要**：日志内容应类似 Git commit message 风格，简洁明了，一句话说清楚
- **决策留痕**：技术决策类日志必须包含决策理由，方便后续追溯
- **问题闭环**：`problem` 和 `fix` 应成对出现，问题记录后解决时也要记录
- **避免冗余**：不要为每个小改动都写日志，只在关键节点写入

## 规则五：手动指令支持

用户可以通过以下指令手动控制 Kanban 同步：

| 用户指令 | 对应操作 |
|---------|---------|
| "同步项目到看板" | 创建项目并拆解任务 |
| "把XX任务改为进行中" | update_task({ status: "in_progress" }) |
| "把XX任务改为已完成" | update_task({ status: "done" }) |
| "查看项目进度" | get_project_stats |
| "查看所有任务" | list_tasks |
| "写一条开发日志" | add_dev_log({ eventType, content, author }) |
| "查看XX任务的开发日志" | get_task({ taskId }) 查看devLogs字段 |

## 规则六：项目上下文管理

AI 应在对话中维护当前项目的上下文信息：

1. **记录当前项目ID**：创建或切换项目后，记住当前 projectId
2. **记录当前模块**：正在开发的模块名称和对应的 taskId
3. **避免重复操作**：如果任务已经是 `in_progress` 状态，不要重复更新

## 排除条件

- 如果当前项目就是 Vibe Kanban 本身（目录名包含 "vibe kanban"），不需要同步到看板
- 如果用户明确表示不需要同步，则跳过

## 重要提醒

- 所有 Kanban 操作必须通过 MCP 工具完成，不要直接调用 API
- 创建项目时必须传入 `modules` 参数进行任务拆解，不要创建空项目
- 状态同步是强制性的，不能跳过
- 如果 MCP 工具调用失败，应告知用户并建议手动在 Kanban 网页端操作
